الشريحة 01 / نظرة عامة

🌟 مقدمة المشروع وأهدافه الاستراتيجية

TrustFix هو منظومة ذكية متكاملة لإدارة خدمات الصيانة والمرافق، تجمع بين قوة الذكاء الاصطناعي لتشخيص الأعطال، ونظام الدفع الضامن (Escrow) لحماية المعاملات المالية، ومؤشر الثقة (Trust Score) لضمان أعلى معايير الجودة، وتعمل المنظومة من خلال 3 تطبيقات موبايل مترابطة بالإضافة إلى ويب أبلكيشن لوحة التحكم (Dashboard):

📱 1. تطبيق العميل / المنشأة

لطلب الصيانة بسهولة عبر التصوير أو التسجيل الصوتي للأفراد والمنشآت.

🛠️ 2. تطبيق الفني

واجهة مبسطة لاستقبال الأعطال، عرض الخريطة، وتأكيد استلام وإنهاء المهام.

🏢 3. تطبيق شركة الصيانة

تطبيق مخصص لشركات الصيانة لمتابعة وإدارة عملياتها وفرقها الميدانية.

💻 4. ويب أبلكيشن الداش بورد

لوحة تحكم شاملة على الويب لإدارة التذاكر، الفنيين، الشكاوى، والتقارير.

🛡️ بناء الثقة الكاملة

القضاء على الخوف المتبادل بين العميل والفني من خلال تجميد قيمة الصيانة في حساب وسيط آمن لا يُصرف إلا بعد إتمام العمل بنجاح.

🧠 أتمتة التشخيص بالـ AI

تمكين أي عميل أو منشأة من طلب الصيانة بمجرد تصوير العطل أو تسجيل مقطع صوتي دون الحاجة لأي خبرة فنية مسبقة.

📈 الصيانة التنبؤية للمنشآت

حماية الشركات والمستشفيات من الأعطال المفاجئة عبر التنبؤ بمواعيد الصيانة قبل وقوع العطل الفعلي.

⚖️ العدالة وحوكمة الجودة

فلترة الفنيين باستمرار وترشيح الأكفأ بناءً على تقييمات الأداء الفعلي وعدم تكرار الأعطال.

الشريحة 02 / دوافع المشروع

⚠️ المشكلة التي خُلق من أجلها التطبيق

1. أزمة الثقة والخوف المتبادل

العميل يخشى دفع المال والتعرض للنصب أو استلام عمل غير متقن، وفي المقابل يخشى الفني إنجاز شغله ثم مماطلة العميل في سداد حقه المالي.

2. صعوبة توصيف الأعطال فنياً

العميل لا يعرف كيفية شرح العطل بدقة، مما يؤدي لحضور الفني بدون الأدوات اللازمة أو تقدير خاطئ لدرجة خطورة المشكلة.

3. الحلول المؤقتة وتكرار الأعطال

غياب الرقابة يسمح لبعض الفنيين بتقديم إصلاحات ظاهرية ("كروتة")، فيعود العطل للظهور بعد أيام دون وجود آلية تحاسب الفني أو تحمي العميل.

4. الخسائر الناتجة عن الأعطال المفاجئة

في قطاع المنشآت والمستشفيات، انتظار تعطل الأجهزة الحيوية يؤدي لتوقف العمل وخسائر كبيرة نتيجة غياب الصيانة التنبؤية.

الشريحة 03 / شرائح السوق

🎯 من يستهدف تطبيق TrustFix؟

🏠 الأفراد والمنشآت (B2C & B2B)

الأفراد في المنازل، وكذلك المنشآت (كالمستشفيات والمصانع) التي تحتاج إلى نظام تذاكر (Tickets) منظم، وصيانة تنبؤية لأجهزتها، مع ضمان أمان المدفوعات وعزل تام لبيانات كل منشأة.

🏢 شركات الصيانة

الشركات المقدمة لخدمات الصيانة التي ترغب في إدارة أسطول الفنيين، متابعة الطلبات الجارية والشكاوى عبر تطبيق الشركة.

🔧 الفنيون المحترفون

الفنيون الباحثون عن منصة تضمن أتعابهم المالية فور انتهاء العمل، وتكافئ التزامهم وجودة شغلهم بمزيد من الطلبات عبر مؤشر الـ Trust Score.

الشريحة 04 / القيمة التنافسية

💎 المميزات التنافسية (شرح تفصيلي)

1. نظام الدفع الضامن (Escrow System) المؤمّن

يحمي النظام أموال العميل/المنشأة وأتعاب الفني من خلال حجز القيمة المالية في السيرفر حتى انتهاء المهمة. وتم تأمين هذا المسار برمجياً عبر تقنية Database Transactions لضمان إتمام العملية المالية بنسبة 100% أو إلغائها بالكامل (Rollback) في حال انقطاع الإنترنت أثناء الدفع.

1. العميل يدفع القيمة ⬅ 2. تجميد المبلغ في الـ Escrow ⬅ 3. الفني ينجز العمل والعميل يؤكد ⬅ 4. فك التجميد والتحويل لمحفظة الفني

2. التشخيص الذكي والترشيح التلقائي عبر Gemini API

بدلاً من كتابة نصوص معقدة أو اضطرار العميل للبحث يدوياً بين تخصصات الفنيين المختلفة (مثل أقسام التبريد والتكييف، الصيانة الكهربائية، والأعطال الميكانيكية)، يلتقط العميل صورة للعطل أو يسجل مقطعاً صوتياً. يقوم النظام بإرسالها إلى Gemini API الذي يحللها بدقة عالية، لا ليعيد فقط ملف JSON يوضح نوع العطل، درجة الخطورة، والأدوات المتوقعة، بل ليقوم الذكاء الاصطناعي تلقائياً بفلترة وتوجيه العميل مباشرة إلى قائمة الفنيين المتخصصين بدقة في نوع المشكلة المطلوبة. حيث يربط النظام الشكوى مباشرة بنوع التخصص المطلوب داخل شبكة الفنيين المسجلين، مما يلغي عشوائية البحث اليدوي ويضمن وصول العميل للفني الأكفأ لمشكلته في أسرع وقت ممكن.

3. مؤشر الثقة (Trust Score) ومنع "الكروتة"

يرتبط جدول تذاكر الصيانة بجدول التقييمات بعلاقات مباشرة، بحيث ينعكس تقييم كل عملية فوراً على ملف الفني. ويتميز النظام بتطبيق خصم قوي جداً على تقييم الفني في حال "تكرار نفس العطل" بعد مغادرته، مما يضمن التزام الفني بأعلى جودة ممكنة.

4. محرك التوجيه الذكي (Smart Routing) والصيانة التنبؤية

التوجيه الذكي: يوازن اللوغاريتم بين المسافة والـ Trust Score؛ فيختار الفني الممتاز الأبعد قليلاً بدلاً من الفني القريب ذي التقييم السيء.
الصيانة التنبؤية: يدرس النظام عوامل الاستهلاك والبيئة (مثل تأثير درجة حرارة الجو على أعطال التكييفات) لتنبيه المنشآت بموعد الصيانة قبل تعطل الجهاز.

5. عزل البيانات والأمن السيبراني (Data Isolation)

تطبيق معايير صارمة لعزل بيانات الشركات والمنشآت، حيث لا يمكن لمدير شركة (أ) الاطلاع نهائياً على طلبات أو فواتير شركة (ب)، إذ يتم ربط كل استعلام بالـ ID الخاص بالشركة فقط.

الشريحة 05 / الهيكلة والتنفيذ

🛠️ خطة العمل وتوزيع المهام التقنية

📱 فريق الواجهات (3 تطبيقات + Web Dashboard)

العمل بمعمارية Clean Architecture وتوحيد الـ Theme عبر المنصات الأربع مع تخصيص الـ Layout:
• تطبيق العميل / المنشأة: شاشة مبسطة لتصوير العطل أو تسجيل الصوت.
• تطبيق الفني: شاشة واضحة تعرض العطل والخريطة وزر الموافقة والإنهاء.
• تطبيق شركة الصيانة: متابعة وإدارة عمليات الصيانة الميدانية.
• ويب أبلكيشن الداش بورد: لوحة تحكم ويب لمتابعة الطلبات الشغالة، الفنيين المتاحين، والشكاوى.

⚙️ فريق Backend & Database

• بناء قاعدة البيانات وربط جداول التذاكر بجدول الـ Trust Score عبر Relations دقيقة.
• تطوير واجهات البرمجة (APIs) لخدمة الـ 3 تطبيقات وويب الداش بورد.
• برمجة منطق الـ Escrow وتأمينه بنظام الـ Transactions.

🧠 فريق الذكاء الاصطناعي (AI)

• ربط Gemini API وتصميم الـ Prompts لإخراج نتائج بصيغة JSON وترشيح التخصص المناسب.
• إعداد بيانات محاكاة (Dummy Data) تشمل عوامل مثل الحرارة لبناء نموذج الصيانة التنبؤية.
• تطوير خوارزمية التوجيه الموزونة بين المسافة والتقييم.

📊 فريق البيانات والأمن السيبراني

• تصميم معادلة الـ Trust Score وتحديد أوزان الخصم عند تكرار الأعطال.
• تطبيق سياسات عزل البيانات (Data Isolation) ومراجعة صلاحيات الوصول لكل شركة.

الشريحة 06 / خارطة الطريق (6 أشهر)

⏳ الخطة الزمنية للمشروع (أكتوبر 2026 – مارس 2027)

الشهر الأول: أكتوبر 2026 أسابيع 1 - 4

التأسيس، تحليل الأعمال، وبناء المعمارية (Foundation & Architecture)

  • توحيد الرؤية العامة للمشروع وتحديد متطلبات شرائح العملاء (الأفراد، المنشآت، وشركات الصيانة).
  • تجهيز بيئة العمل وتقسيم فولدرات التطبيقات بنظام Clean Architecture وتوحيد الـ Theme.
  • تصميم مخطط قاعدة البيانات (Schema) وعلاقات الجداول (Relations) وتحديد معادلة الـ Trust Score.
الشهر الثاني: نوفمبر 2026 أسابيع 5 - 8

تطوير الواجهات الأربع وبناء النواة البرمجية (UI/UX & Core Backend)

  • بناء شاشات الـ 3 تطبيقات (العميل/المنشأة، الفني، شركة الصيانة) بالإضافة إلى ويب أبلكيشن الداش بورد.
  • برمجة الـ APIs الأساسية لإدارة الطلبات والتقييمات، وتأسيس قواعد عزل البيانات (Data Isolation) بين الشركات.
الشهر الثالث: ديسمبر 2026 أسابيع 9 - 12

تطوير محركات الذكاء الاصطناعي ونظام الدفع الضامن (AI & Escrow Logic)

  • برمجة دورة حياة الأموال في نظام الـ Escrow (تجميد وتحويل) وتأمينها بالكامل عبر Database Transactions.
  • ربط Gemini API لتحليل الصور والمقاطع الصوتية، وترشيح التخصص المناسب وإرجاع مخرجات JSON منظمة.
  • تجهيز الـ Dummy Data (شاملة العوامل البيئية كدرجة الحرارة) لتدريب نموذج الصيانة التنبؤية، وبرمجة خوارزمية التوجيه الذكي.
الشهر الرابع: يناير 2027 أسابيع 13 - 16 (فترة امتحانات نصف العام)

الربط المبدئي ومراجعة منتصف المدة (Initial Integration & Mid-Year Review)

  • إجراء الربط الأولي بين الـ 3 تطبيقات وويب الداش بورد مع واجهات الـ Backend APIs.
  • مراجعة جودة الأكواد وتخفيف ضغط المهام مراعاة لفترة امتحانات الفصل الدراسي الأول.
الشهر الخامس: فبراير 2027 أسابيع 17 - 20

التكامل الشامل للنظام والميزات المتقدمة (Full System Integration)

  • الربط الكامل بين تطبيقات الموبايل، ويب الداش بورد، السيرفر، ومخرجات الـ AI وخوارزمية التوجيه في مسار عمل حي.
  • تفعيل نظام الخصم التلقائي القوي في الـ Trust Score عند تكرار الأعطال، وإضافة الميزات التكميلية بمرونة.
الشهر السادس: مارس 2027 أسابيع 21 - 24 (التسليم النهائي)

اختبار الجودة، فحص الأمان، وتجهيز المناقشة (QA, Security Audit & Final Pitch)

  • اختبار السيناريوهات الحرجة (مثل انقطاع الإنترنت أثناء الدفع) للتأكد من كفاءة الـ Rollback في الـ Transactions.
  • إجراء اختبارات الأمان والتأكد التام من عزل بيانات كل شركة عن الشركات المنافسة (Data Isolation).
  • إتمام التوثيق النهائي وتجهيز العرض التقديمي والنسخة النهائية للمناقشة.
